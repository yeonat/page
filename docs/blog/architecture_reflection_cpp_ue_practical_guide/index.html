Arquitectura de Memoria, Reflexión y C++ en Unreal Engine: Guía Práctica

Aprende cómo interactúan el recolector de basura, las interfaces reflejadas y la memoria de Unreal.

Imagen por Parinaz Mirhosseini.

Uno de los mayores choques culturales al pasar de C++ estándar a Unreal Engine es descubrir que el motor no utiliza punteros convencionales para gestionar el ciclo de vida de sus objetos principales.

Confiar en new/delete o punteros crudos ( UObject*) conduce inevitablemente a los dos peores dolores de cabeza en producción:

  • Memory leaks causados por objetos fuera del alcance del Garbage Collector.
  • Crashes por dangling pointers cuando intentas acceder a punteros destruidos por el Garbage Collector (GC).

En este artículo exploraremos la arquitectura de memoria interna de Unreal Engine, su sistema de reflexión y cómo implementar un sistema de inventario modular con streaming asíncrono y control por consola.

1. Fundamentos: Memoria Nativa vs. Memoria Gestionada

Unreal Engine divide el universo de memoria en dos grandes ecosistemas (que nunca deben mezclarse):

A. Tipos Nativos de C++ (No- UObject)

Para clases y estructuras estándar que no heredan de UObject, Unreal implementa su propia familia de punteros inteligentes de alto rendimiento con soporte para configuración de concurrencia:

  • TSharedPtr<T>: Puntero con conteo de referencias intrínseco (equivalente a std::shared_ptr).
  • TWeakPtr<T>: Rompe ciclos de referencia sin retener la propiedad ni alterar el contador de referencias duras.
  • TUniquePtr<T>: Propiedad exclusiva (equivalente a std::unique_ptr).

B. Tipos Gestionados por el Garbage Collector ( UObject)

Cualquier clase derivada de UObject se ubica en el array global de objetos ( FUObjectArray) y su ciclo de vida lo gobierna el Garbage Collector (GC).

  • Un puntero crudo a un UObject* que no esté marcado con la macro UPROPERTY() es invisible para el Garbage Collector. Si no existen otras referencias fuertes registradas, el GC lo destruirá en su siguiente ciclo ( CollectGarbage), dejando una dirección de memoria huérfana (dangling pointer).

  • El peligro de los punteros crudos: Un Null Check clásico if (RawPointer != nullptr) no protege contra crashes. Si el GC ya recicló la memoria, el puntero seguirá conteniendo una dirección numérica válida en apariencia, pero acceder a sus miembros provocará una violación de acceso inmediata.

  • La solución ( TWeakObjectPtr<T>): Especializado para UObject. No retiene el objeto ni impide que el GC lo destruya, pero TWeakObjectPtr::IsValid() consulta los metadatos internos del motor. Si el objeto fue recolectado, devuelve false de forma segura.

2. El Sistema de Reflexión y el Unreal Header Tool (UHT)

C++ carece por diseño de introspección y reflexión en tiempo de ejecución. Para resolver esto, Epic Games diseñó el Unreal Header Tool (UHT), un preprocesador que analiza las macros antes de invocar al compilador nativo (MSVC/Clang) y genera código auxiliar de metadatos ( .generated.h):

  • Reflexión: Permite que el motor conozca los nombres, tipos y firmas de propiedades y métodos en runtime. Es la columna vertebral de la serialización a disco, la replicación en red, el inspector del editor y la interoperabilidad con Blueprints.

  • USTRUCT(BlueprintType): Estructuras de datos ligeras que se pasan por copia o valor. No tienen recolección de basura propia, pero sus propiedades internas pueden albergar macros UPROPERTY()() para que el GC rastree los objetos anidados.

  • UFUNCTION(...): Expone métodos a Blueprints ( USTRUCT(BlueprintCallable)), al sistema de timers, delegados dinámicos o llamadas a consola ( USTRUCT(Exec)).

La dualidad de las Interfaces ( UInterface vs IInterface)

Las interfaces estándar de C++ basadas en herencia múltiple pura rompen el sistema de reflexión de Blueprints. Unreal resuelve esto dividiendo cada interfaz en dos clases hermanas:

  • UItemModifierInterface: Hereda de UInterface. Está vacía y sirve exclusivamente como ancla de reflexión para el UHT y los metadatos.

  • IItemModifierInterface: La interfaz C++ pura con métodos virtuales puros que las clases implementan directamente en código nativo.

3. Manejo de Assets: Carga Síncrona vs Streaming Asíncrono

Un puntero duro directo ( UPROPERTY() UStaticMesh* Mesh;) obliga al motor a cargar el modelo 3D y todas sus texturas en memoria RAM en cuanto se lee la estructura o clase.

Si un inventario contiene 200 ítems, el juego intentará cargar los 200 modelos al mismo tiempo, congelando el hilo del juego (Game Thread Hitch).

  • TSoftObjectPtr<T>: Solo almacena la ruta del asset ( FSoftObjectPath) consumiendo pocos bytes.

  • FStreamableManager: Permite solicitar la carga en segundo plano ( RequestAsyncLoad) únicamente cuando el ítem se necesita en el juego.

Ejercicio Práctico

Vamos a implementar un inventario modular que carga mallas asíncronamente y permite probar el GC de forma segura.

Paso 1: La Interfaz ( ItemModifierInterface.h)

#pragma once

#include "CoreMinimal.h"
#include "UObject/Interface.h"
#include "ItemModifierInterface.generated.h"

UINTERFACE(MinimalAPI, Blueprintable)
class UItemModifierInterface : public UInterface
{
    GENERATED_BODY()
};

class YOURPROJECT_API IItemModifierInterface
{
    GENERATED_BODY()

public:
    virtual void ApplyModifier(class AActor* TargetActor) = 0;
};

Paso 2: La Definición de Datos y el Ítem ( ItemData.h)

Observa cómo el UInventoryItemInstance es un UObject puro: no es un AActor, por lo que no consume recursos de físicas, colisiones ni ticks en el mundo.

#pragma once

#include "CoreMinimal.h"
#include "Engine/StaticMesh.h"
#include "ItemModifierInterface.h"
#include "ItemData.generated.h"

USTRUCT(BlueprintType)
struct FItemDefinition
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Item Data")
    FText ItemName;

    // Referencia suave: NO carga la malla a memoria al inicializar la estructura
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Item Data")
    TSoftObjectPtr<UStaticMesh> VisualMesh;

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Item Data")
    float PowerValue = 10.0f;
};

// Instancia lógica ligera del ítem en memoria (UObject puro, no un Actor pesado)
UCLASS(BlueprintType)
class YOURPROJECT_API UInventoryItemInstance : public UObject, public IItemModifierInterface
{
    GENERATED_BODY()

public:
    UPROPERTY(VisibleAnywhere, Category = "Item")
    FItemDefinition Data;

    virtual void ApplyModifier(AActor* TargetActor) override
    {
        if (!TargetActor) return;
        UE_LOG(LogTemp, Warning, TEXT("Aplicando efecto del item: %s con poder: %f"), 
            *Data.ItemName.ToString(), Data.PowerValue);
    }
};

Paso 3: El Gestor de Inventario ( InventoryComponent)

Este componente gestiona las referencias fuertes para el GC, ofrece protección con punteros débiles y expone un delegado dinámico para sincronizar la UI en tiempo real.

InventoryComponent.h 
#pragma once

#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "Engine/StreamableManager.h"
#include "ItemData.h"
#include "InventoryComponent.generated.h"

UCLASS(ClassGroup=(Custom), meta=(BlueprintSpawnableComponent))
class YOURPROJECT_API UInventoryComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    UInventoryComponent();

    UFUNCTION(BlueprintCallable, Category = "Inventory")
    void AddNewItem(FItemDefinition NewItemData);

    UFUNCTION(BlueprintCallable, Category = "Inventory")
    void EquipItemAsync(int32 ItemIndex, UStaticMeshComponent* TargetMeshComp);

    // [CORRECCIÓN]: Función para cancelar cargas previas y evitar condiciones de carrera
    UFUNCTION(BlueprintCallable, Category = "Inventory")
    void CancelCurrentLoad();

    UFUNCTION(BlueprintCallable, Category = "Debug")
    void RunGCTest();

protected:
    // Limpieza segura si el componente se destruye a mitad de una carga
    virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;

private:
    // Referencias fuertes rastreadas por el Garbage Collector
    UPROPERTY()
    TArray<UInventoryItemInstance*> Items;

    // Puntero débil: se auto-invalida si el ítem es destruido por el GC
    TWeakObjectPtr<UInventoryItemInstance> InspectedItem;

    FStreamableManager StreamableManager;
    TSharedPtr<FStreamableHandle> AssetLoadHandle;

    void OnMeshLoaded(TSoftObjectPtr<UStaticMesh> MeshPath,
                    UStaticMeshComponent* TargetMeshComp);
};
InventoryComponent.cpp 
#include "InventoryComponent.h"
#include "Engine/Engine.h"

UInventoryComponent::UInventoryComponent()
{
    PrimaryComponentTick.bCanEverTick = false;
}

void UInventoryComponent::AddNewItem(FItemDefinition NewItemData)
{
    // NewObject aloja el UObject en el pool gestionado por Unreal
    UInventoryItemInstance* NewItem = NewObject<UInventoryItemInstance>(this);
    NewItem->Data = NewItemData;

    // Al guardarlo en un TArray con UPROPERTY(), el GC sabe que tiene una referencia fuerte
    Items.Add(NewItem);

    // Asignamos el puntero débil para inspección segura
    InspectedItem = NewItem;

    UE_LOG(LogTemp, Log, TEXT("Item %s añadido correctamente."), *NewItemData.ItemName.ToString());
}

void UInventoryComponent::CancelCurrentLoad()
{
    // Si hay una carga previa en progreso, la cancelamos para que su callback no se dispare
    if (AssetLoadHandle.IsValid() && AssetLoadHandle->IsLoadingInProgress())
    {
        AssetLoadHandle->CancelHandle();
        UE_LOG(LogTemp, Warning, TEXT("Carga asíncrona anterior cancelada."));
    }
    AssetLoadHandle.Reset();
}

void UInventoryComponent::EquipItemAsync(int32 ItemIndex, UStaticMeshComponent* TargetMeshComp)
{
    if (!Items.IsValidIndex(ItemIndex) || !TargetMeshComp) return;

    // Evitamos carreras cancelando cualquier streaming previo
    CancelCurrentLoad();

    TSoftObjectPtr<UStaticMesh> MeshSoftPtr = Items[ItemIndex]->Data.VisualMesh;

    if (MeshSoftPtr.IsNull())
    {
        TargetMeshComp->SetStaticMesh(nullptr);
        return;
    }

    // Si ya está en memoria RAM, lo asignamos directamente
    if (MeshSoftPtr.IsValid())
    {
        TargetMeshComp->SetStaticMesh(MeshSoftPtr.Get());
        return;
    }

    // Si no está en RAM, pedimos la carga asíncrona en segundo plano
    AssetLoadHandle = StreamableManager.RequestAsyncLoad(
        MeshSoftPtr.ToSoftObjectPath(),
        FStreamableDelegate::CreateUObject(this, &UInventoryComponent::OnMeshLoaded, MeshSoftPtr, TargetMeshComp)
    );
}

void UInventoryComponent::OnMeshLoaded(TSoftObjectPtr<UStaticMesh> MeshPath, UStaticMeshComponent* TargetMeshComp)
{
    // Verificamos que el handle no haya sido cancelado en el último instante
    if (!AssetLoadHandle.IsValid()) return;

    if (TargetMeshComp && MeshPath.IsValid())
    {
        TargetMeshComp->SetStaticMesh(MeshPath.Get());
        UE_LOG(LogTemp, Log, TEXT("Mesh cargado asincrónicamente y asignado con éxito."));
    }
}

void UInventoryComponent::RunGCTest()
{
    UE_LOG(LogTemp, Warning, TEXT("--- Iniciando prueba de GC ---"));

    if (InspectedItem.IsValid())
    {
        UE_LOG(LogTemp, Log, TEXT("Antes de vaciar: InspectedItem es VÁLIDO (%s)"), 
            *InspectedItem->Data.ItemName.ToString());
    }

    // Rompemos la única referencia fuerte que protegía a los UInventoryItemInstance
    Items.Empty();

    // Forzamos al motor a ejecutar una pasada completa de Garbage Collection
    GEngine->ForceGarbageCollection(true);

    // [ACLARACIÓN]: Lo que el GC recolectó fue el UObject lógico, no el Actor en el nivel
    if (!InspectedItem.IsValid())
    {
        UE_LOG(LogTemp, Error, TEXT("Después de GC: InspectedItem se invalidó de forma segura sin causar crash."));
    }
    else
    {
        UE_LOG(LogTemp, Warning, TEXT("El objeto aún está en memoria."));
    }
}

void UInventoryComponent::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
    CancelCurrentLoad();
    Super::EndPlay(EndPlayReason);
}

4. Control por Consola (UFUNCTION(Exec))

Para probar este flujo en el editor sin construir una interfaz compleja de botones, creamos un PlayerController que expone comandos de consola accesibles pulsando la tecla ~:

TestPlayerController.h 
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/PlayerController.h"
#include "InventoryComponent.h"
#include "TestPlayerController.generated.h"

UCLASS()
class YOURPROJECT_API ATestPlayerController : public APlayerController
{
    GENERATED_BODY()

public:
    UFUNCTION(Exec)
    void AddItem(int32 ItemID);

    UFUNCTION(Exec)
    void EquipItem(int32 ItemIndex);

    UFUNCTION(Exec)
    void TestGC();

private:
    UInventoryComponent* GetInventory() const;
    UStaticMeshComponent* GetTargetMeshComponent() const;
    FItemDefinition CreateDummyItem(int32 ItemID);
};
TestPlayerController.cpp 
#include "TestPlayerController.h"
#include "GameFramework/Character.h"
#include "Components/StaticMeshComponent.h"
#include "Engine/Engine.h"

UInventoryComponent* ATestPlayerController::GetInventory() const
{
    APawn* CurrentPawn = GetPawn();
    return CurrentPawn ? CurrentPawn->FindComponentByClass<UInventoryComponent>() : nullptr;
}

UStaticMeshComponent* ATestPlayerController::GetTargetMeshComponent() const
{
    APawn* CurrentPawn = GetPawn();
    return CurrentPawn ? CurrentPawn->FindComponentByClass<UStaticMeshComponent>() : nullptr;
}

FItemDefinition ATestPlayerController::CreateDummyItem(int32 ItemID)
{
    FItemDefinition Item;
    switch (ItemID)
    {
    case 1:
        Item.ItemName = FText::FromString(TEXT("Cubo Básico"));
        Item.PowerValue = 15.0f;
        Item.VisualMesh = TSoftObjectPtr<UStaticMesh>(FSoftObjectPath(TEXT("/Engine/BasicShapes/Cube.Cube")));
        break;
    case 2:
        Item.ItemName = FText::FromString(TEXT("Esfera Mágica"));
        Item.PowerValue = 45.0f;
        Item.VisualMesh = TSoftObjectPtr<UStaticMesh>(FSoftObjectPath(TEXT("/Engine/BasicShapes/Sphere.Sphere")));
        break;
    default:
        Item.ItemName = FText::FromString(TEXT("Ítem Genérico"));
        Item.PowerValue = 5.0f;
        Item.VisualMesh = nullptr;
        break;
    }
    return Item;
}

void ATestPlayerController::AddItem(int32 ItemID)
{
    if (UInventoryComponent* Inv = GetInventory())
    {
        Inv->AddNewItem(CreateDummyItem(ItemID));
    }
}

void ATestPlayerController::EquipItem(int32 ItemIndex)
{
    UInventoryComponent* Inv = GetInventory();
    UStaticMeshComponent* MeshComp = GetTargetMeshComponent();
    if (Inv && MeshComp)
    {
        Inv->EquipItemAsync(ItemIndex, MeshComp);
    }
}

void ATestPlayerController::TestGC()
{
    if (UInventoryComponent* Inv = GetInventory())
    {
        Inv->RunGCTest();
    }
}

Desmitificando el Garbage Collector en Runtime

Un malentendido común al ejecutar RunGCTest() es asumir que el modelo 3D desaparecerá del nivel o se descargará de la memoria VRAM de inmediato. Hay tres entidades distintas en juego:

  • La Instancia Lógica ( UInventoryItemInstance): Al hacer Items.Empty(), se destruye su única referencia fuerte. El GC la elimina de la memoria en la pasada forzada, razón por la cual InspectedItem.IsValid() pasa a false.

  • El Actor y su Componente en el Nivel: Siguen intactos en la escena. Si el componente tenía asignada una malla, la seguirá dibujando.

  • El Asset 3D ( UStaticMesh): Permanece en memoria RAM/VRAM mientras esté referenciado por el UStaticMeshComponent. Solo se descargará si se desasigna explícitamente ( SetStaticMesh(nullptr)), se libera el AssetLoadHandle y se ejecuta una recolección de paquetes no referenciados.

Tres puntos clave sobre el manejo de memoria y arquitectura interna en Unreal Engine:

  • Evitar Bloqueos del Game Thread: Explicar cómo TSoftObjectPtr combinado con FStreamableManager::RequestAsyncLoad traslada la lectura pesada del disco a hilos secundarios, evitando caídas de cuadros (hitches) al abrir o cambiar de ítems.

  • Seguridad contra Dangling Pointers: Demostrar por qué TWeakObjectPtr es superior a comprobar if (Ptr != nullptr). Un puntero crudo sigue apuntando a la dirección de memoria tras el reciclaje del GC provocando crashes; TWeakObjectPtr::IsValid() consulta el estado real del objeto en el sistema de reflexión.

  • Polimorfismo Compatible con Reflexión: Defender la separación UInterface/IInterface explicando que el UHT necesita la clase con macro reflejada para exponer la interfaz a Blueprints, serialización y red sin acoplamiento rígido de clases.
