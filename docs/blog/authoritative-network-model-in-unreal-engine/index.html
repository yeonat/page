Networking Autoritativo en Unreal Engine C++: Guía Práctica

Aprende paso a paso el flujo cliente-servidor en C++ y pruébalo con latencia simulada en el editor.

Imagen por Andrei Marinho.

El mayor error al abordar el multijugador en Unreal Engine es programar pensando como si el juego corriera en una sola máquina. En un entorno de red, cada acción debe responder a tres preguntas: ¿Quién tiene la verdad?, ¿Por dónde viaja el dato? y ¿Cómo evitamos que un cliente haga trampa o sature la red?

1: El Modelo de Autoridad ( HasAuthority)

En Unreal Engine el servidor es el árbitro absoluto del estado del juego. Los clientes son terminales que envían intenciones (inputs) y reciben la simulación resultante.

El motor asigna a cada máquina un rol de red ( ENetRole) sobre cada actor:

  • ROLE_Authority: El servidor; el único con permiso para restar salud, gastar recursos o spawnear proyectiles con colisión real.

  • ROLE_AutonomousProxy: El cliente local que controla directamente a su personaje; lee la entrada del teclado y predice movimiento local.

  • ROLE_SimulatedProxy: Los otros jugadores en la pantalla de un cliente; solo interpolan la posición y el estado que el servidor les envía.

2: Replicación de Variables y RepNotify ( OnRep)

Una vez que el servidor cambia un valor, ese dato debe viajar a los clientes. Las variables replicadas tienen una regla: fluyen en un único sentido, de Servidor a Cliente. Un cliente jamás puede replicar una variable hacia el servidor.

  • ReplicatedUsing = FunctionName: Asigna una función RepNotify que el motor ejecuta en los clientes cuando la variable llega modificada desde la red.

  • DOREPLIFETIME_CONDITION: Permite filtrar qué clientes reciben la variable. Por ejemplo, tu maná solo lo necesita tu propia pantalla (COND_OwnerOnly), ahorrando ancho de banda en los otros 99 jugadores de la partida.

  • El comportamiento en el Servidor: OnRep no se ejecuta automáticamente en el servidor. Si estás corriendo un Listen Server (donde el host también juega), debes llamar a la función OnRep manualmente tras cambiar el valor para que su propia interfaz gráfica se entere del cambio.

3 Remote Procedure Calls (RPCs)

Cuando un cliente necesita pedirle algo al servidor (como lanzar un hechizo) o el servidor necesita notificar un evento efímero (como un sonido o partículas), las variables no alcanzan; se usan RPCs.

Tipo de RPC ¿Quién lo llama? ¿Dónde se ejecuta? Uso Idea
Server Owning Client Server Peticiones críticas (disparar, usar habilidad, comprar)
Client Server Owning Client Notificaciones privadas (misiones, logros, alertas UI)
NetMulticast Server Server + Todos los Clientes Cosméticos globales (explosiones, sonidos, partículas)

El Parámetro de Fiabilidad: Reliable vs Unreliable

  • Reliable: Garantiza entrega en orden (retransmite si se pierde). Costoso. Solo para gameplay crítico donde perder un paquete rompería la partida.

  • Unreliable: Se descarta ante congestión de paquetes UDP. Ideal para cosméticos. Si una partícula no se dibuja en un cliente con lag, el juego continúa sin desincronizar la simulación.

Uniendo todos los eslabones anteriores, crearemos un personaje que gestione salud autoritativa, habilidad validada por red y efectos visuales en multicast.

Paso 2: Definición de la Clase ( NetCharacter.h)

#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Character.h"
#include "NetCharacter.generated.h"

CLASS()
class YOURPROJECT_API ANetCharacter : public ACharacter
{
    GENERATED_BODY()

public:
    ANetCharacter();

    // Registro obligatorio de variables replicadas
    virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override;

    // Disparado por el input local (tecla de habilidad)
    UFUNCTION(BlueprintCallable, Category = "Gameplay")
    void CastAbility();

    // Modificación de salud autoritativa
    virtual float TakeDamage(float DamageAmount, struct FDamageEvent const& DamageEvent, 
                             class AController* EventInstigator, AActor* DamageCauser) override;

protected:
    // --- ESTADO REPLICADO ---
    // Salud: visible para todos, ejecuta OnRep al sincronizar
    UPROPERTY(ReplicatedUsing = OnRep_CurrentHealth, VisibleAnywhere, Category = "Stats")
    float CurrentHealth;

    UPROPERTY(EditDefaultsOnly, Category = "Stats")
    float MaxHealth = 100.0f;

    // Maná: solo se replica al cliente propietario (optimización de ancho de banda)
    UPROPERTY(Replicated, VisibleAnywhere, Category = "Stats")
    int32 ManaPoints;

    UFUNCTION()
    void OnRep_CurrentHealth(float OldHealth);

    // --- RPCs ---
    // El cliente solicita al servidor ejecutar la habilidad con validación estricta
    UFUNCTION(Server, Reliable, WithValidation)
    void Server_CastAbility();

    // El servidor avisa a todos los clientes que reproduzcan los efectos visuales
    UFUNCTION(NetMulticast, Unreliable)
    void Multicast_PlayAbilityFX();
};

Paso 3: Lógica Autoritativa y Replicación ( NetCharacter.cpp)

#include "NetCharacter.h"
#include "Net/UnrealNetwork.h"
#include "Engine/Engine.h"

ANetCharacter::ANetCharacter()
{
    // Habilitar replicación de red en el Actor
    bReplicates = true;

    // Optimización: tasa de sincronización de red
    NetUpdateFrequency = 66.0f;

    CurrentHealth = 100.0f;
    ManaPoints = 50;
}

void ANetCharacter::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);

    // Replicar salud a todas las máquinas conectadas
    DOREPLIFETIME(ANetCharacter, CurrentHealth);

    // [OPTIMIZACIÓN]: Maná solo viaja al dueño de este peón (OwnerOnly)
    DOREPLIFETIME_CONDITION(ANetCharacter, ManaPoints, COND_OwnerOnly);
}

void ANetCharacter::CastAbility()
{
    // 1. Verificación de propiedad: solo el cliente dueño puede enviar este input
    if (!IsLocallyControlled())
    {
        return;
    }

    // 2. Predicción de UI del lado del cliente: chequeo rápido antes de emitir tráfico
    if (ManaPoints < 10)
    {
        if (GEngine) GEngine->AddOnScreenDebugMessage(-1, 2.0f, FColor::Yellow, TEXT("[Cliente] Maná insuficiente."));
        return;
    }

    // 3. Invocar RPC Server (Unreal lo encamina automáticamente al servidor)
    Server_CastAbility();
}

// VALIDACIÓN ANTITRAMPAS (Corre en el Servidor antes de la implementación)
bool ANetCharacter::Server_CastAbility_Validate()
{
    const int32 AbilityCost = 10;

    // El servidor comprueba si la petición es físicamente y lógicamente posible
    if (CurrentHealth <= 0.0f || ManaPoints < AbilityCost)
    {
        // Retornar false indica paquete anómalo / intento de exploit
        return false;
    }

    return true;
}

// EJECUCIÓN AUTORITATIVA (Corre exclusivamente en el Servidor)
void ANetCharacter::Server_CastAbility_Implementation()
{
    const int32 AbilityCost = 10;

    // Mutación autoritativa del estado
    ManaPoints -= AbilityCost;

    // Ordenar a todos los clientes que reproduzcan el cosmético
    Multicast_PlayAbilityFX();

    if (GEngine)
    {
        GEngine->AddOnScreenDebugMessage(-1, 3.0f, FColor::Green, 
            FString::Printf(TEXT("[Servidor] Habilidad aprobada. Maná restante: %d"), ManaPoints));
    }
}

// EFECTO COSMÉTICO (Corre en Servidor y todos los Clientes remotos)
void ANetCharacter::Multicast_PlayAbilityFX_Implementation()
{
    // Al ser Unreliable, si hay congestión de red no bloqueará datos críticos
    if (GEngine)
    {
        GEngine->AddOnScreenDebugMessage(-1, 2.5f, FColor::Cyan, 
            FString::Printf(TEXT("[FX] Partículas y sonido reproducidos en NetMode: %d"), (int32)GetNetMode()));
    }
}

float ANetCharacter::TakeDamage(float DamageAmount, FDamageEvent const& DamageEvent, 
                               AController* EventInstigator, AActor* DamageCauser)
{
    // Regla de Oro: Solo el Servidor tiene potestad de reducir salud
    if (!HasAuthority())
    {
        return 0.0f;
    }

    const float ActualDamage = Super::TakeDamage(DamageAmount, DamageEvent, EventInstigator, DamageCauser);
    const float OldHealth = CurrentHealth;

    CurrentHealth = FMath::Clamp(CurrentHealth - ActualDamage, 0.0f, MaxHealth);

    // En el Servidor, OnRep no se invoca automáticamente; lo llamamos manualmente para coherencia de eventos
    OnRep_CurrentHealth(OldHealth);

    return ActualDamage;
}

void ANetCharacter::OnRep_CurrentHealth(float OldHealth)
{
    // Se ejecuta en clientes receptores cuando llega la variable modificada
    if (GEngine)
    {
        GEngine->AddOnScreenDebugMessage(-1, 4.0f, FColor::Red, 
            FString::Printf(TEXT("[OnRep] Salud actualizada de %.1f a %.1f"), OldHealth, CurrentHealth));
    }

6: Verificación en el Editor con Latencia Simulada

Probar multijugador con latencia cero en tu propia máquina oculta errores de sincronización y condiciones de carrera. Para simular condiciones reales:

Paso 1:

En el editor, ve al botón desplegable de Play, Configura Number of Players en 2 y Net Mode en Play As Listen Server o Play As Client

Paso 2:

En la ventana del cliente, abre la consola ( ~) y simula una conexión deficiente con 200 ms de ping y 5% de pérdida de paquetes:

Net PktLag=200 Net PktLoss=5

Paso 3:

Llama a CastAbility:

  • Observa cómo el RPC Server_CastAbility espera los 200 ms para validar en el servidor sin desincronizar la simulación.

  • El evento Multicast_PlayAbilityFX reproduce el efecto cosmético de forma desacoplada.

  • Al aplicar daño en el servidor, OnRep_CurrentHealth actualiza la salud del cliente sin que el cliente haya tenido que solicitarla por un RPC manual.
